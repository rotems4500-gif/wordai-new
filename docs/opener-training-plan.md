# תוכנית אימון — פתיחים ברמת מילה + שלד מסמך, אפס API בזמן ריצה

מטרה: שלד מסמך לפי סעיפים + ציטוטים מהמקורות + פתיח בסגנון המשתמש לכל סעיף — בלי קריאת API אחת בזמן ריצה. מודלים זולים (Gemini Flash / Haiku) מותרים רק **אופליין**, לבניית דאטה ולשיפוט ב-LAB.

עיקרון מרכזי (דרישת המוצר): לאמן על **מילים בודדות בתפקידים**, לא משפטים שלמים — כדי שהמנוע ירכיב וריאציות ולא ישלוף תבנית אחת.

---

## שלב 0 — מדידת בסיס (חינם, יום עבודה)

הרנס כבר קיים ולא רץ אף פעם. בלי מספר בסיס אין "אימון".

1. `node tools/test-bench/run-openers-labelset.mjs` על `real-corpus/finals`.
2. תיוג ידני ב-HTML labeler (`make-labeler.mjs`) → `opener-labels.json`.
3. סקריפט ציון: precision (פתיחים שהוצעו והם באמת ניסוח-שלי) + recall (פתיחים טובים שנדחו, לפי שורות ה-reject בסט).
4. שמירת התוצאה כ-baseline ב-`tools/test-bench/lab-results/openers-baseline.json`.

תוצר: מספר. כל שינוי בהמשך נמדד מולו.

## שלב 1 — אימון גלובלי: דקדוק פתיחים ברמת מילה

הרעיון: לפרק פתיח אקדמי עברי ל-**חריצים (slots)**, ולתייג מילים לחריצים:

```
[מחבר/קישור]? [עמדת-כותב]? [פועל-מסגור] [התייחסות]  →  "לסיכום, ניתן לומר כי..."
slot: connector   stance      framing-verb  reference
```

1. **סכמת חריצים** — connector / stance / framing-verb / reference / hedge, לכל אחת מ-7 כוונות הסעיף הקיימות (`OPENER_CUES`: intro, review, method, findings, analysis, comparison, conclusion).
2. **תיוג הלקסיקון במודל זול, חד-פעמי**: batch של 5,724 הלמות + מילות פונקציה מהקורפוס דרך Gemini Flash (או Haiku) — לכל מילה: אילו חריצים, אילו כוונות, משלב (אקדמי/דיבורי). ~60 batches של 100, עלות אגורות. רץ ב-`tools/` (בסגנון `tools/synonyms-build`), לא באפליקציה.
3. **ולידציה במודל זול כשופט**: דגימת 500 תיוגים → שיפוט חוזר, תיקון ידני של קטגוריות עם הסכמה נמוכה (אותו דפוס כמו community synonyms — אימות AI לכל 100).
4. **תוצר sharable**: `src/services/openerGrammar.data.js` — קובץ סטטי בפורמט של `synonymsLexicon.data.js`: `intent → slot → [words]`. נטען lazy, אפס רשת.
5. **מנוע הרכבה** ב-`styleOpenerService`: בוחר מילה לכל חריץ → מרכיב 3–5 וריאציות פתיח לכל סעיף. אקראיות מבוקרת כדי שלא יחזור על עצמו בין סעיפים.

## שלב 2 — אימון אישי לכל משתמש

הגלובלי הוא ברירת המחדל (פותר cold-start — היום משתמש חדש מקבל כלום). האישי דורס אותו בהדרגה:

1. **פירוק פתיחי המשתמש לחריצים**: על כל פתיח שנכרה מהקורפוס (`collectOpenerCandidates`) — התאמה מול הדקדוק: אילו מילים המשתמש שם בכל חריץ, ובאיזו תדירות. דטרמיניסטי, מקומי.
2. **משקלים אישיים**: `intent → slot → {word: count}` נשמר ב-IndexedDB (`wordai_opener_profile_v1`), עם fingerprint של הקורפוס לרענון — אותו דפוס בדיוק כמו `styleAutocompleteService` (schema version + fingerprint).
3. **מיזוג**: בהרכבה — מילה של המשתמש אם קיימת בחריץ (משקל לפי מס' מסמכים, כמו `MIN_PREFIX_DOCS`), אחרת מהגלובלי. יחס blend עולה עם גודל הקורפוס.
4. **לולאת פידבק**: קבלה/דחייה של פתיח בעורך → עדכון משקלים (חיבור ל-`tagStyleSample` הקיים). זה "האימון האישי" השוטף — בלי מודל בכלל.

## שלב 3 — לולאת הערכה (LAB, מודל זול כשופט אופליין)

1. הרחבת `run-openers-labelset.mjs`: מצב `--composed` — מריץ את מנוע ההרכבה על סעיפי מבחן ומוציא CSV.
2. **שופט זול אופליין** (Flash): לכל פתיח מורכב — תקין תחבירית? מתאים לכוונת הסעיף? נשמע כמו הכותב (מול 3 דוגמאות מהקורפוס)? רק ב-LAB, אף פעם בזמן ריצה.
3. **שופט מקומי משלים**: `styleAuthenticityService` נותן ציון "נשמע גנרי" לכל פתיח מורכב — פילטר חינמי גם בזמן ריצה (לזרוק וריאציות שנשמעות AI).
4. שער רגרסיה: ציון מתחת ל-baseline של שלב 0 → לא ממזגים.

## שלב 4 — אינטגרציה ומוצר

1. חיווט לשלד: `assignmentPrepService` — לכל סעיף בפנקס: כותרת + ציטוטי ראיות (קיים) + 3 וריאציות פתיח מורכבות (חדש). סעיף בלי ראיות נשאר `blocked` — לא נוגעים בעיקרון.
2. UI ב-EvidencePanel: בחירת וריאציה / ריענון / "עוד כמו זה" — כל לחיצה מזינה את שלב 2.4.
3. מצבי דלילות: קורפוס ריק → גלובלי בלבד עם תווית "כללי"; קורפוס חלקי → blend; אף פעם לא מסך ריק.
4. QA: הרצת labelset מלאה + בדיקת e2e בשלד על מטלה אמיתית; תיקון/קבלה של fallback הלקסיקלי בדפדפן (onnxruntime backend נכשל ב-preview — ראיות עובדות דרך fallback).

## סטטוס ביצוע (2026-07-22)

**נבנה והורץ:**
- שלב 0: ה-harness רץ (24 עבודות, 329 מועמדים, 53 לתיוג) → labeler על שולחן העבודה (`תיוג-פתיחים.html`). **ממתין לתיוג ידני — runbook בסוף המסמך.** בלי זה אין baseline, ו-`openers-gate.mjs` משווה מול ריק.
- שלב 1: סכמה הוקפאה — 9 אינטנטים קנוניים (הוספו cues ל-argument/exposition), סלוטים `connector/stance/framingVerb(inf|fin)/reference/hedge/subjectNP` עם `{g,n}` + `tails`. שתי משפחות תבניות (אימפרסונלית / נושא-עם-סינון-צורות) = התאם מובטח בלי מודל. seed ידני ~180 ערכים + תיוג Flash של הלקסיקון (`tools/opener-grammar-build/build.mjs`, checkpoint/resume) → `src/services/openerGrammar.data.js` (lazy). מנוע הרכבה: `composeOpeners` ב-`styleOpenerService` (RNG זרוע, ייחודיות וריאנטים, הצלבת tails).
- שלב 2: `openerProfileService.js` — כרייה (decomposeOpener, התאמת טוקנים בלי `\b`), משקלים `wordai_opener_profile_v1`, משוב insert/refresh, מיזוג `score = base·(1+λ·boost)`, `λ=min(0.8, docs/10)`. עובד על הקורפוס האמיתי (23 מסמכים).
- שלב 3: `judge-composed-openers.mjs` (שופט Flash), `openers-gate.mjs` (דקדוקיות ≥95%, התאמה ≥85%, precision מול baseline), `validate.mjs` (שיפוט התיוג).
- שלב 4: `assignmentPrepService` — פתיח תמיד נפתר (ממוקש/מנוסח-עבורך/כללי); `EvidencePanel` — תגיות, ↻ רענון עם משוב שלילי, insert עם משוב חיובי.

**פקודות ה-LAB:**
```bash
node tools/test-bench/run-openers-compose.mjs     # הרכבה: 9×5, התאם, דטרמיניזם
node tools/test-bench/run-opener-profile.mjs      # אימון אישי על הקורפוס האמיתי
node tools/test-bench/judge-composed-openers.mjs  # שופט Flash
node tools/test-bench/openers-gate.mjs            # שער רגרסיה
node tools/test-bench/score-openers.mjs           # אחרי תיוג ידני → baseline
```

**תוצאות האימון הגלובלי (2026-07-22):** תיוג Flash של כל 5,724 הלמות (58 אצוות, ~אגורות) → 275 תיוגים גולמיים. צנרת גיזום בשלוש שכבות ב-build.mjs: (א) מחלקות סגורות — stance/connector/hedge מה-seed בלבד (connectors אוטומטיים "על מנת"/"מתוך ש" הפילו דקדוקיות ל-69%); (ב) תכונות סותרות — צורת שטח אחת עם כמה `{g,n}` = הזיית מתייג, נזרקת ("הדגים" תויג m/s וגם f/p); (ג) BLOCKLIST ממשוב שופט-המשפטים (העריך, מצביע-כי, להשפיע…). בנוסף שומר-שורש במנוע ("נקודת הדמיון הבולטת בולטת"). ציוני שופט סופיים: **דקדוקיות 97.8%, התאמת אינטנט 93.3% — שער ירוק**. המודול הסופי 21KB, chunk lazy נפרד.

**פתוח:** תיוג ידני של רותם — **ממתין לתיוג ידני, runbook למטה** (baseline; ה-labeler בשולחן העבודה) · מסנן styleAuthenticityService על וריאנטים בזמן ריצה (nice-to-have).

## Runbook — מדידת הבסיס של שלב 0 (תיוג ידני)

שלושה צעדים, ~20 דקות. אין רשת ואין מפתחות — הכול מקומי.

**1. לתייג.** לפתוח בדפדפן:

```
C:/Users/rotem/OneDrive/שולחן העבודה/תיוג-פתיחים.html
```

קובץ HTML עצמאי (הכרטיסים מוטמעים בתוכו — אין שרת, השורות לא עוזבות את המכונה).
53 כרטיסים, לכל אחד שלוש תשובות:

| כפתור | מקש | משמעות |
|---|---|---|
| כן — ניסוח שלי | חץ ימינה → | `כ` — זה **ניסוח**, פתיח לשימוש חוזר |
| לא — תוכן/שם | חץ שמאלה ← | `ל` — זה תוכן ספציפי, לא פתיח |
| לא בטוח | רווח | `?` — לא נספר בציון |

Backspace = אחורה (מוחק את התיוג של הכרטיס הקודם). ההתקדמות נשמרת ב-localStorage,
אפשר לעצור באמצע ולחזור. **לתייג את כל 53** — `?` הוא לא תיוג.

**2. לייצא.** בסיום → כפתור **«שמור קובץ»** → `opener-labels.json` יורד לתיקיית ההורדות
(`~/Downloads`). אפשר גם להעתיק את ה-JSON מהתיבה שנפתחת בסוף.

**3. לצייַן.**

```bash
node tools/test-bench/score-openers.mjs
# ברירת מחדל: ~/Downloads/opener-labels.json — או להעביר נתיב:
node tools/test-bench/score-openers.mjs D:/somewhere/opener-labels.json
```

הפלט נכתב ל-**`tools/test-bench/lab-results/openers-baseline.json`** (התיקייה gitignored):
`precision` (מתוך הנשמרים — כמה באמת ניסוח שלי), `recall` (כמה טובים נפסלו),
ופירוק **אבדות לפי סיבת פסילה** — זו הטבלה שאומרת איזה מסנן לכוונן.
מאותו רגע `openers-gate.mjs` מודד מול המספר הזה.

**אם ה-HTML לא קיים בשולחן העבודה** — לייצר מחדש:

```bash
node tools/test-bench/run-openers-labelset.mjs   # מועמדים -> tools/test-bench/lab-results/openers-labelset/
node tools/test-bench/make-labeler.mjs           # -> תיוג-פתיחים.html בשולחן העבודה
```

עקיפות: `WORDAI_LABELSET_OUT` (תיקיית המועמדים, משותפת לשני הסקריפטים) ·
`WORDAI_LABELER_OUT` (יעד ה-HTML) · `WORDAI_CORPUS_OUT` (הקורפוס) ·
`WORDAI_LABELSET_REBUILD=0` (דילוג על בניית הבאנדל).
