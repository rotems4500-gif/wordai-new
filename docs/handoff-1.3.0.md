# מסירה: בניית 1.3.0 במחשב הישן

**נכתב:** 28.7.2026 · **נכתב מ:** המכונה החדשה (`C:/Users/rotem_7jta`) · **מיועד ל:** המכונה שבנתה את 1.2.0

---

## למה הכל עבר אליך

המכונה החדשה **מעולם לא בנתה את האפליקציה**: אין בה Visual Studio Installer,
אין `link.exe`, אין Windows SDK, ואין Rust. נבדק, לא הונח.

מכאן נגזר גם איפה מפתח החתימה. חיפשתי אותו בחמש דרכים במכונה החדשה — לפי שם קובץ
על כל C:, לפי תוכן בפרופיל ובסל המיחזור, בהיסטוריית git של **שני** המאגרים,
במשתני הסביבה, וב-`.env.local` שנפרס מהגשר. הוא לא שם באף אחת מהן.
**הוא אמור להיות אצלך**, כי `tauri signer generate` יצר אותו במכונה שבנתה.

## הצעד הראשון — שתי שניות, וכל השאר תלוי בו

```bash
ls ~/.tauri/
```

### אם `wordflow-updater-v2.key` שם ✅

הדרך הזולה. משתמשי 1.2.0 יתעדכנו ל-1.3.0 **אוטומטית**, בלי להתקין כלום ידנית.
לא נוגעים ב-`pubkey` שב-`tauri.conf.json`.

⚠️ שים לב שאתה חותם ב-**`-v2.key`** ולא ב-`wordflow-updater.key` הישן. חתימה בישן
מפיקה עדכון שכל לקוח דוחה בשקט. `npm run desktop:release` חוסם את זה — הוא משווה
את מזהה המפתח שבחתימה מול ה-pubkey, וה-id הנכון הוא **`a204a227b85a1c67`**
(אומת מול החתימה שפורסמה ב-1.2.0).

### אם הוא לא שם ❌

מייצרים חדש:

```bash
npx tauri signer generate -w ~/.tauri/wordflow-updater-v3.key
```

ה-pubkey שיודפס נכנס ל-`src-tauri/tauri.conf.json` תחת `plugins.updater.pubkey`.

**המחיר:** מי שמותקן לו 1.2.0 לא יתעדכן — ה-pubkey החדש לא תואם למה שצרוב אצלו.
הוא יצטרך להוריד ידנית מהאתר, וכרטיס ההורדה החדש במסך הבית נותן בדיוק את זה.
זה מחיר קטן: בדקתי את הקוד כפי שנשלח ב-1.2.0, ושם כפתור ההתקנה מותנה בסטטוס
`'downloaded'` שצד ה-Rust לא מייצר לעולם — כלומר **אצלם העדכון האוטומטי לא עבד
מעולם**. לא נלקח מהם דבר שהיה להם.

**וגבה את המפתח החדש מחוץ ל-git.** מנהל סיסמאות או כונן חיצוני, לא קומיט.

## הבנייה

1. להעלות את הגרסה ל-`1.3.0` ב-**`package.json` וגם ב-`src-tauri/tauri.conf.json`**.
   `desktop:release` עוצר אם הם לא מסכימים.
2. ```bash
   npm run desktop:build
   ```
3. ```bash
   npm run desktop:release
   ```
   בונה את `latest.json`, מאמת את מזהה המפתח, ומדפיס אילו שני קבצים להעלות
   ל-release בתג `v1.3.0`. ר' [scripts/make-latest-json.mjs](../scripts/make-latest-json.mjs).

## ⚠️ מה שלא אומת ואתה תגלה ראשון

**[src-tauri/src/updater.rs](../src-tauri/src/updater.rs) לא עבר קומפילציה.**
בלי Rust במכונה החדשה אי אפשר היה לבדוק. השינוי מוסיף דיווח התקדמות הורדה דרך
אירוע `app-update-status` (פונקציה רגילה ולא closures, כדי להימנע מהסקת lifetimes).
אם `cargo` יתלונן — זה המקום היחיד שנגעתי בו ב-Rust.

## מה נכנס ל-1.3.0

הדסקטופ עומד על 1.2.0 מ-30.6, כ-80 קומיטים אחורה. הגרסה הזו מביאה:

- **מנוע ה-NLG המקומי** ושלד המטלה — כתיבה בלי אף קריאת API.
- **עדכון אוטומטי שעובד.** שלושה מבואות סתומים תוקנו: כפתור התקנה שהיה קיים רק
  לסטטוס שאינו מיוצר, `onAppUpdateStatus` שהיה stub, ופקודת "בדיקת עדכונים"
  שזרקה את התוצאה. בדיקה 12 שניות אחרי הפתיחה ואז כל 6 שעות, toast עם "עדכן
  עכשיו", השתקה 3 ימים.
- **כרטיס הורדה באתר** + הסבר לאזהרת SmartScreen.
- **הבהרת דרגה ב-onboarding** — מה מקבלים בלי מפתח API ומה המחיר (32 מול 59).

## פתוח אצלך, ורק אצלך

**`neg-ai-labor`.** הקורפוס של תרחיש 1 נמצא אצלך ולא במכונה החדשה, ולכן הבדיקה
**לא רצה שם בכלל** — היא לא עברה ולא נכשלה. אין בידינו אף מכונה שבה היא **עוברת**,
ולכן ההסבר "הבדל בתוכן הקורפוס" נשאר בלי ראיה תומכת. הייתי מתייחס לזה כחולשת
אחזור אמיתית עד שיוכח אחרת. הפירוט: [docs/bench-neg-ai-labor.md](bench-neg-ai-labor.md).

הבנצ' כבר לא ישקר לך על זה: דילוג על בדיקה מחייבת מפיק `⚠ bench חלקי` במקום
`✓ ירוק`, ו-`WORDAI_BENCH_STRICT=1` הופך אותו לכישלון.
