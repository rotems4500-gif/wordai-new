# nlg-bench — הבדיקה הקבועה של המודל הפנימי

מודד את מנוע ה-NLG המקומי (proseCompose + אחזור + סגנון) בשתי שכבות שנועדו
בדיוק למנוע קיבוע (overfitting לבנצ'מרק):

## שכבה 1: רגרסיה — מקובעת בכוונה
`run-scaffold-e2e.mjs` כמו שהוא: תשובות-ידועות + בקרות-שליליות + אינווריאנטות
מבנה. סרגל שלא זז. עבר/נכשל.

## שכבה 2: יכולת — משתנה בכל ריצה
- **אינווריאנטות של תכונות** (invariants.mjs): עיגון ≥40% לכל משפט-תוכן,
  אפס-ג'יבריש, כנות-חסימה, כנות-מכסה, אי-כפילות, אפס-דליפת-תבנית. נבדקות על
  כל קלט — אי אפשר להתאים אליהן קוד בלי לקיים אותן באמת.
- **תשובה מול פיגום** (יולי 2026) — שלוש אינווריאנטות שנוספו אחרי שהתגלה פלט
  שעבר את *כל* השערים הקודמים ועדיין לא היה תשובה, אלא רצף פתיחים סביב ציטוטים:
  - `scaffold-budget` — שיעור המילים במשפטים בלי ראיה (פתיח/סיכום/מעבר).
    נמדד 15-28%; שער 35%, **יעד ≤15%**.
  - `copy-budget` — שיעור מילות התוכן המועתקות מילה-במילה מהמקור.
    נמדד 54-81%; שער 85%, **יעד ≤40%**. מעל לכך זו גם חשיפה אקדמית, לא רק סגנון.
  - `answers-the-question` — כמה מהישויות שבשאלה ("יקיר", "דליה") מוזכרות בגוף
    התשובה. נמדד 2/7; שער 25%, **יעד ≥80%**. תשובה שאינה מזכירה את מי שהשאלה
    עוסקת בו הציגה רקע ולא ענתה.

  ⚠️ שלושתם **שערי רגרסיה בלבד** — מכוילים מעט מתחת למצב שנמדד, ולכן מעבר בהם
  אינו הצלחה. היעדים יתהדקו כששכבת הניסוח תיכנס.
- **וריאציות מוגרלות-בזרע** (variations.mjs): ניסוח מוחלף, סדר שאלות מעורבל,
  רעש רווחים — דטרמיניסטי לפי זרע (נשמר ב-history ⇒ כל כשל משוחזר).
- **מקרים אמיתיים מצטברים** (cases/): כל מטלה אמיתית שמריצים באפליקציה ראויה
  להפוך לתיקיית case (assignment.txt + case.json). הבנצ'מרק גדל עם השימוש.

### שדות `case.json`

- `corpusRel` — שורש הקורפוס, **יחסי לשולחן העבודה של המשתמש**. ההרנס מנסה
  `~/OneDrive/שולחן העבודה`, `~/OneDrive/Desktop`, `~/Desktop`, `~` — בסדר הזה.
  עובר כ-`WORDAI_SCAFFOLD_CORPUS`.
- `courseSubdir` — **התיקייה שממנה נסקים חומרי הקורס**, יחסית ל-`corpusRel`.
  בלעדיה ההרנס נופל לרשימת קבצים קשיחה בתוך `nlg-loop-round.mjs` (מצגות קורס
  הפילוסופיה), וכל case — יהיה הקורפוס שלו אשר יהיה — סורק את אותם קבצים.
  **זה השדה שמייחד case.**
- `requiredFiles` — קבצי-סימן, ל-case שאין לו `courseSubdir`. אם אף אחד מהם לא
  קיים, ה-case מדולג.
- `expectations.minCapabilityScore` — רף. מתחתיו exit 1.

⚠️ **`corpusDir`/`courseDir` המוחלטים נתמכים לתאימות אחורה בלבד — אל תוסיף אותם
ל-case חדש.** עד 27.7.26 הם החזיקו נתיב עם **שם המשתמש בתוכו**
(`C:/Users/rotem_7jta/...`). ברגע שהפיתוח עבר לשתי מכונות שני ה-cases דולגו,
שכבת הרגרסיה נפלה על "קבצים חסרים", והבנצ' דיווח אדום שנראה בדיוק כמו נסיגת קוד
— בזמן שהקורפוס ישב על הדיסק תחת בית אחר. עקיפה ידנית: `WORDAI_BENCH_CORPUS`.

### קבצי OneDrive שלא ירדו

⚠️ קובץ במצב Files On-Demand **קיים** ל-`existsSync` ובכל זאת `readFileSync`
עליו זורק `UNKNOWN` (errno -4094) — הוא placeholder בענן. ההרנס מדלג עליו
ברעש (`⚠ לא ירד מ-OneDrive`) במקום ליפול; לפני התיקון קובץ ענן יחיד הפיל את כל
הריצה עם stack של `node:fs`.

### דילוג מפורש כשאין קורפוס

⚠️ case בלי קורפוס **אינו נכשל — הוא משקר.** ההרנס סורק אפס קבצים, כל הסעיפים
נחסמים כ"אין ראיות בסף הרלוונטיות", והבנצ' מדווח ציון נמוך כאילו המנוע נסוג.
כך `mill-2026` החזיר exit 1 קבוע מ-25.7.26 — ושער שתמיד אדום שקול לשער כבוי.

עכשיו קורפוס חסר ⇒ דילוג רועש שאינו מפיל את ה-exit code. **אבל דילוג על כל
ה-cases כן מפיל אותו** — בנצ' ששכבת היכולת שלו ריקה מדווח ירוק בלי שמדד דבר,
וזה בדיוק הכשל השקט שהדילוג בא למנוע.

### שלושה מצבים, לא שניים

⚠️ הדילוג פתר בעיה אחת ויצר אחרת: **דילוג נספר כהצלחה.** ב-`scaffold-e2e`
תרחיש מדולג משאיר `{requiredOk: 0, required: 0}`, והתנאי `requiredOk === required`
מתקיים על `0 === 0`. ב-27.7.26 זה הצהיר `✓ bench ירוק` בזמן ש-`neg-ai-labor` —
בקרה שלילית **מחייבת**, זו שנכשלה במכונה השנייה — לא רצה בכלל.

לכן הפלט מבחין עכשיו בין שלושה מצבים:

| מצב | exit | מתי |
|------|-----:|------|
| `✓ bench ירוק` | 0 | הכול רץ והכול עבר |
| `⚠ bench חלקי` | 0 | מה שרץ עבר, אבל בדיקה מחייבת דולגה |
| `✗ bench אדום` | 1 | נסיגה אמיתית |

"חלקי" נשאר exit 0 בכוונה — אחרת מכונה בלי קורפוס אדומה תמיד, וזה חוזר בדיוק
לכשל שסעיף זה מתאר. **`WORDAI_BENCH_STRICT=1` הופך דילוג לכישלון** — זו הצורה
להריץ ב-CI ולפני release, שם "לא נבדק" אינו תשובה מספקת.

הפירוט עובר מ-`scaffold-e2e` ל-`run.mjs` דרך
`.scaffolde2e-scratch/e2e-status.json`, ולא דרך קוד היציאה: ה-`stdio` הוא
`inherit`, ולהעמיס ערך שלישי על ה-exit code היה שובר את החוזה
`exit≠0 = רגרסיה`.

## ציון
capabilityScore = 60% אינווריאנטות (כנות לפני תפוקה) + 25% כיסוי סעיפים +
15% מילוי מכסה. כל ריצה נרשמת ב-`bench-history.jsonl` (תאריך, commit, זרע,
ציונים) — ירידה מול הריצה הקודמת ⇒ exit 1.

## הרצה
```bash
npm run bench:nlg
```
זרע: ברירת מחדל נגזר מהתאריך; `WORDAI_BENCH_SEED=x` לשחזור כשל.

## סבב מלא על מטלה אמיתית (nlg-loop-round)

הרתמה הזאת אינה חלק מ-`bench:nlg` — היא מריצה **מטלה אמיתית מקצה לקצה** ואז
מודדת סגנון. ברירות המחדל שלה מצביעות על קבצים שאינם בריפו, ולכן צריך env:

```bash
node tools/test-bench/run-nlg-loop-round.mjs   # WORDAI_NLG_COURSE_DIR, WORDAI_NLG_ASSIGNMENT
node tools/test-bench/style-eval.mjs           # WORDAI_STYLE_SCORE_FILE=<round>/prose-only.txt
node tools/test-bench/style-diff.mjs <file>    # *מה* לתקן, לא רק כמה
```

- `WORDAI_NLG_ASSIGNMENT` מקבל גם PDF/DOCX (מחולץ אוטומטית), לא רק txt.
- `prose-only.txt` נכתב בכל סבב והוא הקלט למדידת הסגנון — **בלי כותרות, בלי
  הערות שוליים**. גרסה ידנית שלו גרמה בעבר לכל הריצות לדווח את אותו ציון.
- מתגים למדידה: `WORDAI_REWRITE=0/1` · `WORDAI_REWRITE_MODEL` · `WORDAI_EV_K` ·
  `WORDAI_STYLE_SHOTS` · `WORDAI_FOCUSED_MIN_Z` · `WORDAI_FRAME_REWRITES=0`.

⚠️ **רזולוציית המדידה: ±3 נקודות סגנון.** שתי ריצות של אותה תצורה בדיוק נתנו
1014 מילים/סגנון 53 ו-1003 מילים/סגנון 50. הפרש קטן מכך אינו אות — אין להכריע
לפיו בין תצורות.
